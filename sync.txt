# Feature Request: LRC Synchronizer — iOS Music App

Implement a new **LRC Synchronizer** feature in my existing iOS music app.

## 1. Integrate into the Existing Library UI

Use the provided Library screenshot as the visual reference.

Add a new Library menu row named **LRC Synchronizer**, positioned exactly between:
- LRC Checker
- Favorites

Match the existing menu rows precisely:
- Same black background.
- Same typography, font sizes, and weights.
- Same red/pink accent color for the leading icon.
- Same row height, horizontal padding, separators, and trailing chevron.
- Use a suitable clock/waveform synchronization icon consistent with the existing SF Symbols style.
- Preserve the current Library layout, navigation, bottom tab bar, spacing, and existing functionality.

Do not redesign the Library screen. This is an addition to the existing app.

## 2. LRC Synchronizer Screen

When the user taps the new row, open a dedicated synchronization screen that follows the app's existing design system and navigation patterns.

The screen must support manually synchronizing lyrics already embedded in local MP3 files.

### Audio and Lyrics Import
- Allow the user to select an MP3 file using the native iOS Files picker.
- Read the embedded unsynchronized lyrics from the MP3's ID3 `USLT` frame, when available.
- Do not require the user to provide a separate `.lrc` or `.txt` file.
- Preserve the original lyrics and metadata unless the user explicitly chooses to modify them.
- If no embedded lyrics are found, display a clear message and offer an appropriate way to provide lyrics.

### Manual Line-by-Line Synchronization
Build an interactive synchronization interface with:
- Song title and artist when available.
- Play/pause controls.
- Current playback time and total duration.
- A progress slider or waveform timeline.
- Lyrics displayed as individual lines.
- A clearly visible **Sync Next Line** button.
- While the audio is playing, tapping the button assigns the current playback timestamp to the selected lyric line and advances to the next line.
- Highlight the current line and clearly indicate which line will receive the next timestamp.
- Allow seeking, pausing, resuming, and retiming previously synchronized lines.
- Allow users to restart synchronization or clear timestamps after confirmation.
- Support repeated choruses and blank lines sensibly.
- Keep the interface usable on different iPhone screen sizes and when the keyboard is visible.

### Save Synchronized Lyrics into MP3
The primary output must be a new MP3 file containing synchronized lyrics embedded in its ID3 tags.

- Write synchronized lyrics using the ID3 `SYLT` frame with appropriate language, text encoding, content descriptor, timestamp format, and timestamp type.
- Preserve unrelated ID3 tags, album artwork, and existing metadata.
- Do not replace the original MP3 by default. Save to a new file and let the user export it using the native iOS share sheet or Files interface.
- Preserve the original `USLT` lyrics unless the user explicitly chooses otherwise.
- Verify that the exported MP3 contains the expected `SYLT` timestamps and can be reopened by the app.
- Display success or actionable error messages.

## 3. Technical Requirements

First inspect the existing project and identify:
- The app's architecture and navigation implementation.
- The current Library screen and reusable row components.
- Existing theme colors, typography, icons, spacing, and design conventions.
- Existing audio playback, metadata, file import/export, and ID3 handling code.
- The project's deployment target and available dependencies.

Reuse existing components and services wherever possible. Follow the project's existing architecture and coding conventions. Avoid duplicating audio playback or metadata logic.

Use SwiftUI and AVFoundation if they match the existing project. Use a reliable ID3 parser/writer library or implement the required frame handling carefully. AVFoundation alone does not provide a complete API for writing arbitrary ID3 `SYLT` frames.

Ensure that file access, security-scoped URLs, temporary files, and export operations are handled correctly.

## 4. Important Implementation Constraints

- Implement the actual working feature, not just a UI mockup.
- Do not rebuild the app or replace existing screens.
- Do not break the Downloader, LRC Checker, Favorites, or existing playback functionality.
- Do not introduce unrelated dependencies or make broad architectural changes.
- Do not assume that changing the filename extension or exporting an `.lrc` file embeds synchronized lyrics into MP3.
- Do not claim `SYLT` support works until the output has been verified.
- Handle malformed MP3 files, missing lyrics, unsupported encodings, and write failures gracefully.
- Keep all file processing local on-device unless the existing architecture explicitly requires otherwise.

## 5. Testing and Acceptance Criteria

Verify the complete workflow:

1. Open Library and confirm LRC Synchronizer appears between LRC Checker and Favorites.
2. Tap it and import an MP3 containing embedded `USLT` lyrics.
3. Confirm the lyrics are extracted and displayed line by line.
4. Play the track and manually timestamp several lines.
5. Retiming a line updates its timestamp correctly.
6. Export a new MP3 containing a valid `SYLT` frame.
7. Reopen the exported MP3 and verify that the timestamps persist.
8. Verify that the original file, album artwork, and unrelated metadata remain intact.
9. Confirm that existing app screens and navigation continue working.

Start by inspecting the existing codebase, then implement the feature in the smallest coherent set of changes. Run the available build and tests, fix any issues, and summarize the files changed, implementation details, and any remaining limitations.
